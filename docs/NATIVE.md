# Native apps (iOS / Android) with Capacitor

The store apps are the same Vite build wrapped by Capacitor. Nothing is
duplicated: the WebView loads `dist/public` from the bundle and calls the
API at `VITE_API_BASE` with a bearer token.

The native projects are committed:

| | Where | Package manager | Generated by |
| --- | --- | --- | --- |
| iOS | `ios/App` (`App.xcodeproj`, `CapApp-SPM/Package.swift`) | Swift Package Manager — no CocoaPods | `npx cap add ios --packagemanager SPM` |
| Android | `android/` (Gradle 8.11, AGP 8.7, SDK 35, minSdk 23, JDK 21) | Gradle | `npx cap add android` |

`cap sync` regenerates `ios/App/CapApp-SPM/Package.swift`, the copied web
assets and the plugin lists; those outputs are git-ignored except
`Package.swift`, which is committed so Xcode resolves on a fresh clone.

## How auth works in the shell

| Browser | Native shell |
| --- | --- |
| Same-origin `/api/*` | `${VITE_API_BASE}/api/*` + CORS for `capacitor://localhost` / `https://localhost` |
| Session cookie | `Authorization: Bearer <jwt>` (same 365-day JWT) |
| Login returns a cookie | Login with header `X-RG-Client: native` also returns `token`; stored in `localStorage` (`rg.auth.token`) |
| Google OAuth redirects to `?next=` | The Google link opens in the **system browser** (Capacitor sends external hosts there, so Google never sees a WebView user agent); the callback redirects to `raritygrid://auth?token=…`; the shell stores it (`consumeAuthDeepLink`, `@capacitor/app` `appUrlOpen`) |
| Logout clears the cookie | Logout also drops the token |

Server side: `authenticateRequest` reads the cookie or the bearer;
`POST /api/auth/token` exchanges a cookie session for a bearer;
`NATIVE_APP_ORIGINS` (env, comma-separated) lists the allowed WebView
origins.

## What is already configured

- **Boot route** — the bundle opens at `/`; `client/src/main.tsx` lands on
  `/app` when `isNative()`.
- **Camera** — `getUserMedia` inside the WebView. Android:
  `android.permission.CAMERA` (+ `uses-feature` not required so tablets
  without a camera can install). iOS: `NSCameraUsageDescription` (EN + PT-BR).
- **Deep link** `raritygrid://auth` — Android `intent-filter` on
  `MainActivity`; iOS `CFBundleURLTypes`.
- **Look** — dark system bars (`android/app/src/main/res/values/{colors,styles}.xml`,
  `plugins.StatusBar` in `capacitor.config.ts`), splash on `#0f0c1a`, iPhone
  locked to portrait (iPad free), `ITSAppUsesNonExemptEncryption=false`.
- **Icons & splash** — `pnpm native:assets` renders `assets/*.png` from the
  RarityGrid mark and fills every iOS/Android size.
- **Web push** — hidden in the shell (`AppAlerts`): WKWebView/Android WebView
  have no Web Push. In-app alerts still work; native push is a later step.
- **Pro checkout** — hidden in the shell (`client/src/app/pro.tsx`): store
  rules forbid web checkout for digital goods inside the app.

## Build from a clean clone

```bash
pnpm install
pnpm build:native          # VITE_API_BASE=https://raritygrid.com vite build && cap sync
pnpm cap:android           # opens Android Studio
pnpm cap:ios               # opens Xcode (Mac only)
```

### Android without Android Studio

The **Android app** workflow (`.github/workflows/android-build.yml`) builds a
debug APK on every change to `android/`, `client/` or `capacitor.config.ts`
and on manual dispatch. Download `raritygrid-debug-apk` from the run and
sideload it. For Google Play you need a release keystore:

```bash
keytool -genkeypair -v -keystore raritygrid-upload.jks -alias upload \
  -keyalg RSA -keysize 2048 -validity 10000
```

Keep it out of git; point `android/app/build.gradle` `signingConfigs.release`
at it (or use Play App Signing) and run `./gradlew bundleRelease` for the `.aab`.

### iOS — the steps that need a Mac

Everything in the repo is done; what remains needs Xcode and an Apple
Developer account (the **iOS app** workflow only proves the Simulator build
compiles):

1. `pnpm install && pnpm build:native && pnpm cap:ios` — Xcode opens
   `ios/App/App.xcodeproj` and resolves the Swift packages (first time:
   1–3 min; `capacitor-swift-pm` comes from GitHub, plugins from
   `node_modules`).
2. Target **App → Signing & Capabilities**: pick your Team; bundle id
   `com.raritygrid.app` (change it there and in `capacitor.config.ts` if the
   id is taken).
3. Run on a device (the Simulator has no rear camera — the scanner needs a
   real iPhone). Test: open at `/app`, scan, sign in with email, sign in with
   Google (Safari opens and returns through `raritygrid://auth`), collection,
   portfolio, alerts, settings.
4. **Product → Archive → Distribute → TestFlight**. Submit to the App Store
   only after RevenueCat/StoreKit replaces the hidden web paywall (see
   below) — a digital subscription sold outside IAP is a rejection.

Optional: Universal Links (`https://raritygrid.com/app/...` opening the app)
need an `apple-app-site-association` file served from the site with the
Team ID, and an Associated Domains capability in Xcode. Android App Links
likewise need `/.well-known/assetlinks.json` with the release certificate
SHA-256. Both are post-launch polish; the custom scheme already covers OAuth.

## Store notes

- In-app purchases: the web Pro checkout must not be shown inside the iOS
  app for digital goods. Before submitting, gate the paywall behind
  RevenueCat (StoreKit / Play Billing) when `isNative()`; keep the web flow
  for browsers. Until then, the native build hides the "Get Pro" button.
- The camera uses `getUserMedia` inside WKWebView (iOS 14.3+), no plugin.
- Capacitor 7 (`@capacitor/*` pinned to `^7.6`). Capacitor 8 exists; upgrade
  deliberately (new Xcode / SDK floors), not via a lockfile bump.
